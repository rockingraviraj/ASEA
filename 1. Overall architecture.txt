4. Policy Engine + Permission Manager

These two look similar, so define them carefully.

Policy Engine

Answers:

"What is allowed?"

Example:

Changing authentication code?
→ high risk


Changing README?
→ low risk


Modifying production workflow?
→ very high risk
Permission Manager

Answers:

"Who/which agent is allowed to do it?"

Example:

Coding Agent
→ read/write src/


Review Agent
→ read-only


Test Agent
→ read + execute tests


Git Agent
→ branch/commit


PR Agent
→ create PR

So:

Policy Engine
    ↓
Is action allowed?


Permission Manager
    ↓
Does this agent have permission?

Keep both.

6. Intelligence Layer — ⭐⭐⭐⭐⭐

Current:

Issue Analysis
Root Cause
Planning
Coding
Test Generation
Recovery
Review

Very good.

But I would not put CI/CD Agent here.

Why?

Because CI/CD is primarily an engineering tool/integration capability.

The AI reasoning that analyzes CI failures belongs to Intelligence, but:

GitHub Actions
Jenkins
GitLab CI

belongs to Tool Layer.

So:

CI/CD Tool
      ↓
Failure logs
      ↓
Recovery Agent
      ↓
Reasoning
      ↓
CI/CD Tool

That's cleaner.

12. Add one missing component: Evidence Store

This is the biggest thing still missing from your architecture.

ASEA shouldn't only say:

Fix successful

It should preserve evidence.

Create:

Evidence Store
Evidence
│
├── Test Results
├── Build Logs
├── Static Analysis
├── Security Results
├── CI Results
├── Code Diff
├── Runtime Logs
├── Root Cause Evidence
└── Review Findings

Then final PR can say:

Why was this fix accepted?


Evidence:
✓ Regression test passed
✓ Full test suite passed
✓ Build passed
✓ Static analysis passed
✓ Security scan passed
✓ CI passed
✓ Review passed

This fits perfectly with your original requirement of producing a validated engineering change with evidence.

16. One architectural rule I want you to remember

This will save you a lot of trouble when we start coding:

❌ Don't build this
Agent → Agent → Agent → Agent
❌ And don't build this
LLM → Shell → Repository
✅ Build this
                 ORCHESTRATOR
                      │
               ┌──────┴──────┐
               ↓             ↓
             AGENT          STATE
               │
               ↓
             CONTEXT
               │
               ↓
             POLICY
               │
               ↓
              TOOL
               │
               ↓
            SANDBOX
               │
               ↓
             RESULT
               │
               ↓
            EVIDENCE
               │
               ↓
          ORCHESTRATOR

That is the architecture that makes ASEA autonomous but controlled.
